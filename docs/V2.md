# Kingdom V2: how the living world works

V1 showed GitHub numbers as RPG cards. V2 is one world. Real GitHub activity changes the state, the state changes the scene,
and a GitHub Action redraws the pictures. There is no JavaScript in the README and no game loop. Motion comes from
CSS animation inside each SVG and from a new frame every time the world changes.

```
GitHub ─► github.mjs ─► state.mjs (V1 logic, unchanged) ─► v2.mjs ─► scene.mjs ─► render/*.mjs ─► renderer/*.svg ─► README
                           │                                 │            │
                           ├ quests.mjs (data/quests.json)   │            └ modes, hero state, people, light, stories
                           └ events.mjs (EVENT_FX table)     └ evolution.mjs, power.mjs
```

## The page (generated between the KINGDOM markers)
hero HUD → living kingdom → world events (only when there are any) → power and quests → project districts (five featured
repositories) → trophy hall → harvest field → kingdom history → visitor camp with two small signposts → guild banners → one status light.
No navigation, no intro text, no legend, no repository list.

## Repository evolution (`engine/evolution.mjs`)
One 0-100 score per repository. Same data in, same level out. No randomness, no clock.

| part | rule | max |
| --- | --- | --- |
| activity | commits in 90 days x 1.5 | 30 |
| recency | pushed in 3 / 14 / 30 / 90 / 180 days = 20 / 15 / 10 / 5 / 2 | 20 |
| maturity | age in days / 20 | 15 |
| depth | log2(1 + all commits) x 2.2 | 15 |
| release | releases x 5 | 10 |
| reputation | stars x 2 + forks x 3 | 10 |

A failing workflow subtracts 15. Caps: archived 9, dusty 27, sleepy 47. Levels: 1 FOUNDATION (<12), 2 FRAME (<28),
3 BUILDING (<48), 4 SPECIALIZED (<72), 5 LANDMARK. **Age rule:** younger than 1 day = level 1, younger than 3 days = at most 2,
younger than 7 = at most 3, so nothing skips construction. Building types come from the V1 archetype rules
(tower, library, mine, workshop, shop, house, castle) plus a new `lab` (research). Overflow moves a repository to the village.

## Kingdom power (`engine/power.mjs`)
`progress 30 x (1 - e^(-level/14))` + `consistency 20 x min(1, streak/30)` + `reliability 20 x workflow health`
+ `reach 15 x (1 - e^(-(stars + 3 forks + 2 followers)/40))` + `vitality 15 x active/all repositories` - `open issues (max 10)`.

## Scene (`engine/scene.mjs`)
Modes, strongest first: RAID, DANGER, STORM, RECOVERY, CELEBRATION, HARVEST, RAIN, SLEEP, NIGHT, WORKING, ACTIVE, IDLE.
Hero states: idle, working, walking, sleeping, celebrating, fighting, traveling (raid → fighting; failing CI → working at the CI;
release / milestone / harvest / victory → celebrating; night or 3+ quiet days → sleeping; dawn and evening → traveling).
`frame` = hash of date, phase, mode, hero state and event ids, modulo 8: stable until the world changes.

**Event pipeline** (table `EVENT_FX` in `events.mjs`): event detected → mode → effects → hero state → light → HUD chip → ends at its `until`
and the scene returns to normal by itself.

**Stories by age** (no random numbers): CI failure `warning <2h → alarm <8h → smoke <24h → fire`; recovery `firefighter <6h → repair <18h → fade <36h`;
new project `foundation <24h → builders <72h → construction <7d`; release `peak <12h` (fireworks, confetti, lights, banners) `→ afterglow` (lights and banners only); visitor `arriving <6h → camping <48h → settled`;
raid `enter (15 min) → battle → won / lost`.

**People** (counts only): builders = buildings pushed in 3 days (max 6); farmers = commits of 7 days / 25 (max 5); miners = 1 + data repositories;
guards = 2 + open issues (max 4) + 2 in a raid; merchants = stars / 8; librarians = knowledge repositories; researchers = lab repositories;
messengers = open PRs + fresh release + forks; villagers = population / 220.

**Words on the map**: only `CI ALERT`, `ISSUES n`, `DEFENSE n%` during a raid, and the banner of a release or workflow emergency.

## Quests (`engine/quests.mjs`, saved in `data/quests.json`)
LOCKED / ACTIVE / COMPLETE, from real numbers: streak ladder 3-7-14-30-60-100, star ladder, clear the gate (open issues),
fix the CI, ship a release (30 days), start a project (30 days). Ladder rungs give XP once (20, 40, 60 ...). Repeatable quests give no XP,
so opening and closing issues cannot farm it. The first run saves goals that are already met as baseline: no XP, no celebration.

## Light, weather, seasons
Everything is drawn in daylight, then `light.mjs` lays a dark veil with holes cut at windows, torches, lamps and fires (SVG mask),
adds warm glow, red danger light around failing buildings, gold at the shrine and lights on the castle for celebrations.
Weather changes the sky, ground (puddles, frozen pond), people (umbrellas, fewer walkers, a hero with an umbrella unless asleep or fighting) and light.
An aurora gets its own night palette (deep teal and violet veil, green, cyan and violet glow); it appears with a release or milestone, as in V1. Seasons change the art itself
(blossom, sunflowers, pumpkins and leaves, snow and a frozen pond), not a label.

## Animation grammar
Animation only appears when it means something: hammer swing = a building was pushed to in 3 days; pulsing red lamp = alarm;
smoke / fire = failing CI; bucket and sparkles = recovery; growing crops and a golden outline = streak; marching goblins and sword flashes = raid;
walking traveler = a new visitor; fireworks and confetti = release or milestone. `prefers-reduced-motion` turns all of it off.

## Visitors and raids
Security is unchanged (`visitors.mjs`, `safety.mjs`). Camp and map only draw approved visitor data. Text goes through the pixel font or `esc()`,
avatars keep the V1 checks, SVG is linted before it is written. A raid reads: available → request → goblins march → guards fight → won / lost.

## Config and commands
`kingdom.config.json`: `featured` (repository names), `featuredCount` (5), `links` (guild banners, https and mailto only), `quests.enabled`.
`node engine/cli.mjs update | render | demo | status | lint | cleanup`. `render` also upgrades a saved V1 `world-state.json` on the fly
(commit counts are estimated until the next real update). `demo` writes 19 scenes to `docs/preview/`.

## Upgrading from V1
- Push the files. The `world-update` workflow starts by itself (it watches `engine/**`) and builds the first real V2 state from GitHub.
  Until then the pictures in `renderer/` come from your last V1 save, with commit counts estimated.
- Goals that are already met (streaks, stars) are saved as baseline on the first run: no XP, no celebration. Your level does not jump.
- Old pictures are deleted by the first run: `stats.svg`, `repos.svg`, `achievements.svg`, `ui/nav-*`, `ui/action-*`.
- The social badges below the generated block moved into `kingdom.config.json` (`links`) and are drawn as guild banners.
- `data/quests.json` is new. Everything else in `data/` keeps its shape.
- V1 stays in your git history. To go back, revert the V2 commit.
